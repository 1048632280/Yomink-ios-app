# Yomink iOS TXT Reader 项目开发文档

## 1. 项目定位

Yomink 是一款 iOS 原生纯本地 TXT 阅读器，目标系统为 iOS 15.5 及以上。

核心目标：

- 轻量、流畅、丝滑、省电。
- 纯本地运行，无网络依赖、无广告、无数据收集。
- 面向 30MB 以下 TXT 文件提供稳定导入、解析、阅读、搜索、过滤、导出能力。
- 阅读状态下 App 内存峰值严格控制在 50MB 以内，静止阅读时 CPU 占用趋近于 0。

核心原则：

- 本地优先：数据只保存在 App 沙盒内，禁止网络请求能力。
- 极致性能：阅读链路避免全书常驻内存，避免静止状态后台计算。
- 系统融合：尊重 iOS 15.5 交互、暗黑模式、文件导入、分享导出等系统能力。
- 渐进实现：先打通高性能阅读闭环，再扩展书架、搜索、过滤、自动阅读等能力。

## 2. 技术架构

### 2.1 技术栈

- UI 架构：SwiftUI + UIKit 混合。
- 数据库：GRDB + SQLite，使用 `DatabasePool` + WAL，适配单写多读的书架/阅读器场景。
- 文件存储：App 沙盒文件系统。
- 最低系统：iOS 15.5。
- 阅读核心：UIKit 承担高性能文本渲染、手势、分页和滚动；SwiftUI 承担页面编排、书架、设置、表单等业务 UI。

### 2.3 SwiftUI 与 UIKit 边界

SwiftUI 负责：

- 主页书架。
- 左右侧边栏。

- 设置页面。
- 书籍详情。
- 搜索结果页。

- 更多选项页。

## 3. 数据与文件存储

### 3.1 文件系统方案

沙盒目录建议：

```text
Documents/
└─ Books/
   └─ {bookId}/
      ├─ content.txt             App 管理的 UTF-8 正文文件，用于阅读与导出
      ├─ chapter_index.json      可选，章节/块索引缓存
      └─ cover_cache/            预留，当前版本可不启用

Library/Application Support/
└─ Database/
   └─ yomink.sqlite
```

原则：

- 导入时将 TXT 转换为 App 管理的 UTF-8 正文文件，不长期保留原始编码文件，减少双倍空间占用。
- 导出以 `content.txt` 为准，导出内容为 UTF-8 TXT；不承诺与导入文件 byte-for-byte 完全一致。
- 删除书籍时同步删除文件目录、缓存、阅读进度、书签、全文索引。

### 3.2 GRDB 数据表建议

`books`

- `id`: UUID。
- `title`: 书名。
- `author`: 作者，可空。
- `intro`: 简介，可空。
- `fileName`: 原始文件名。
- `fileSize`: 文件大小。
- `encoding`: 识别出的编码。
- `wordCount`: 字数。
- `importedAt`: 导入时间。
- `lastReadAt`: 最近阅读时间。
- `groupId`: 所属分组，可空。
- `importSourceDisplayPath`: 导入来源路径，仅用于展示，可空。
- `sourceBookmark`: iOS security-scoped bookmark，可空，用于后续重新访问外部来源文件。
- `sourcePath`: App 沙盒内 UTF-8 正文文件相对路径，真实阅读和导出以此为准。

`groups`

- `id`: UUID。
- `name`: 分组名称。
- `sortOrder`: 排序。
- `createdAt`: 创建时间。

所有数据库日期字段统一存储为 UTC ISO8601 字符串，格式包含 fractional seconds，例如 `2026-05-22T07:30:15.123Z`。代码统一通过 `DatabaseDateFormatter` 编解码，禁止业务层直接手写日期字符串。数据库迁移不使用 `IF NOT EXISTS` 掩盖 schema drift；全新项目阶段应让迁移差异显式失败。

`reading_progress`

- `bookId`: 书籍 ID。
- `chapterId`: 当前章节 ID。
- `chapterOffset`: 当前章节字符偏移或块偏移。
- `globalProgress`: 全书百分比。
- `updatedAt`: 更新时间。

`chapters`

- `id`: UUID。
- `bookId`: 书籍 ID。
- `title`: 章节名。
- `startOffset`: 正文起始偏移。
- `endOffset`: 正文结束偏移。
- `sortOrder`: 章节序号。
- `source`: 章节来源，`regex` 表示章节规则识别，`pseudo` 表示固定文本块兜底切分。

`bookmarks`

- `id`: UUID。
- `bookId`: 书籍 ID。
- `chapterId`: 章节 ID。
- `offset`: 书签位置。
- `preview`: 预览文本。
- `createdAt`: 创建时间。

`search_history`

- `id`: UUID。
- `keyword`: 搜索词。
- `createdAt`: 创建时间。

`filter_rules`

- `id`: UUID。
- `bookId`: 可空；为空表示全局规则。
- `source`: 要过滤的内容。
- `replacement`: 替换内容，可空。
- `createdAt`: 创建时间。

`reading_history`

- `id`: UUID。
- `bookId`: 书籍 ID。
- `chapterId`: 章节 ID。
- `offset`: 阅读位置。
- `readAt`: 阅读时间。

`app_settings`

- `key`: 设置项。
- `value`: JSON 字符串。

可选全文搜索表：

- 使用 SQLite FTS5 或自建倒排索引。
- 优先对章节级内容建立索引，搜索结果返回章节、片段、精确跳转 offset。

触发：

- 点击阅读界面悬浮自动阅读按钮。

行为：

- 页面开始自动匀速滚动。
- 自动阅读状态下，点击屏幕中间不唤出全局菜单。
- 点击屏幕中间仅在底部弹出调速面板。
- 调速时页面保持滚动。
- 面板提供退出自动阅读按钮。

实现原则：

- 使用 `CADisplayLink` 或滚动视图定时驱动时，只有自动阅读开启时才运行。
- 退出自动阅读后必须释放定时器。
- 后台、锁屏、进入其他页面时必须暂停。

## 5. 导入、解析与阅读引擎

### 5.1 编码识别

目标编码：

- UTF-8。
- UTF-8 BOM。
- GBK。
- GB2312。
- GB18030。
- 其他常见中文 TXT 编码可后续扩展。

实现建议：

- 先检测 BOM。
- 再尝试 UTF-8。
- 再使用 CoreFoundation 字符串编码能力尝试 GB18030/GBK。
- 导入后将书籍正文转为 UTF-8 并作为 App 内唯一正文文件，减少阅读阶段反复解码成本。

注意：

- GBK/GB2312 随机 byte offset 到字符 offset 的映射复杂，阅读阶段不应直接依赖原始编码文件做随机字符定位。
- UTF-8 正文文件用于导出、分页、搜索、过滤。

### 5.2 章节识别

候选章节规则按行匹配，使用多行语义。实现时应组合多条规则，而不是只依赖单条正则：

- 中文章节号：`^\s*第\s*([0-9零〇一二两三四五六七八九十百千万]+)\s*[章回节折卷部篇集]\s*(.*)$`。
- 中文卷号：`^\s*卷\s*([0-9零〇一二两三四五六七八九十百千万]+)\s*(.*)$`。
- 英文章节：`^\s*Chapter\s+\d+.*$`，大小写可兼容。
- 数字标题：`^\s*\d+[\.\、]\s*.+$`。
- 特殊短标题：`^\s*(前言|引子|序|序言|序章|楔子|后记)(\s+.*|[:：].*)?$`，以及 `^\s*番外\s*.*$`。

启发式过滤：

- 候选标题行 trim 后长度必须小于 50 个字符，过长行直接排除。
- 标题匹配前应将 Unicode 空白统一归一化为 ASCII 空格；章节 byte offset 仍按 UTF-8 正文文本计算。
- 候选标题行若以常见句末标点或句末标点后的右引号结尾，例如 `。`、`！`、`？`、`。”`、`！”`、`？”`，大概率是正文对话或叙述，应排除；冒号不作为排除条件，因为章节标题常见 `第一章：标题`。
- 数字标题规则（如 `1. 标题`）容易与列表项冲突；若同时存在中文/英文常规章节候选，则数字标题候选数量至少达到 3 个才保留，否则过滤掉。

策略：

- 导入阶段建立章节索引。
- 若未识别到章节，按固定文本块建立伪章节，避免单章过大导致内存压力。
- 伪章节目录标题统一命名为 `第x章`，不使用书名拼接。
- 单个阅读块建议控制在 64KB 到 256KB UTF-8 文本范围内。

### 5.3 分页与进度

阅读位置：

- 使用 `bookId + chapterId + chapterOffset` 作为主位置。
- 使用 `globalProgress` 作为展示和滑块辅助。

分页：

- 根据字体、行距、边距、屏幕尺寸生成当前章节或当前块的页面布局。
- 只缓存当前页、前后页或当前块附近的少量布局结果。
- 排版设置变化后，只重新计算当前附近内容。

进度保存：

- App 进入后台时保存。
- 阅读器退出时保存。
- 页面切换稳定后节流保存。
- 不在每一帧或每一次滚动回调里直接写库。

### 5.4 内容过滤

过滤应用顺序：

- 读取当前章节或文本块。
- 应用过滤规则。
- 再进行布局。

性能约束：

- 过滤规则数量较少时可直接顺序替换。
- 规则数量增长后需要合并策略或按需优化。
- 过滤结果只缓存当前附近内容，避免全书过滤后常驻内存。

### 5.5 全文搜索

优先方案：

- 导入后为章节内容建立 FTS5 索引。
- 搜索返回 `bookId + chapterId + offset + snippet`。

备选方案：

- 若 FTS5 中文分词效果不理想，可实现按章节顺序扫描。
- 扫描必须异步执行，并支持取消。
- 搜索页可允许短暂更高资源使用，但不能影响阅读静止状态。

## 6. 性能与功耗要求

### 6.1 内存

硬性目标：

- 阅读状态下 App 内存峰值严格控制在 50MB 以内。

实现要求：

- 不将整本书完整载入内存作为阅读常态。
- 阅读界面只持有当前块、相邻块、少量页面布局缓存。
- 图片、纹理背景必须小尺寸复用，不可使用大图背景。
- 全文搜索、导入索引任务进入阅读页后必须暂停或降级。

### 6.2 CPU 与功耗

硬性目标：

- 静止阅读时 CPU 占用趋近于 0。
- 禁止静止状态持续计时器、轮询、后台解析、后台索引。

实现要求：

- `CADisplayLink` 只在动画或自动阅读时启用。
- 菜单动画结束后无持续刷新。
- 阅读静止时不触发布局重算。
- 自动保存使用节流和生命周期触发，不高频写库。

### 6.3 动画

目标：

- 翻页和菜单动画 60fps。

实现要求：

- 手势跟手计算轻量化。
- 布局预计算不能阻塞主线程。
- 大文件章节切换需要加载态或预取，避免主线程卡顿。

## 7. 隐私与权限

原则：

- 不申请网络权限。
- 不集成广告 SDK。
- 不集成统计、追踪、崩溃上报 SDK。
- 文件访问只通过用户主动选择。
- 所有阅读数据只保存在本地沙盒。

建议：

- App Transport Security 不添加额外网络例外。
- 后续若需要崩溃诊断，优先使用用户主动导出的本地日志。

## 10. 后续需要确认的问题

这些问题不阻塞工程启动，但会影响具体实现取舍：

1. 是否要求上架 App Store？如果上架，需要提前补充隐私清单、权限说明、审核策略。
2. 是否需要 iCloud 同步？当前需求按纯本地处理，不做同步。
3. 是否需要支持压缩包、EPUB、PDF？当前仅规划 TXT。
4. 书籍封面是否需要自动生成？当前按轻量 TXT 阅读器处理，默认不生成封面。
5. “一键切换至 iOS 系统深色模式”在 iOS 上不能真正修改系统全局外观，建议定义为切换 App/阅读器内部暗黑主题。
6. 50MB 内存峰值非常严格，需要真机 Instruments 验证；模拟器数据只能作为参考。

## 11. 给 Codex 的开发约束

开发时必须遵守：

- 优先实现阅读器 MVP，再扩展附属功能。
- 所有文件路径必须使用沙盒相对路径入库，避免绝对路径迁移问题。
- 不引入网络、广告、追踪、统计 SDK。
- 不在阅读静止状态运行定时器、轮询、后台索引。
- 不把整本书作为阅读常态常驻内存。
- 任何删除书籍逻辑必须同时清理数据库记录和文件目录。
- 任何影响阅读布局的设置变化必须触发可控重排，并保存设置。
- UI 文案使用 `Localizable.strings` key，避免页面增多后再整体迁移本地化。
- 性能优化以 Instruments 真机数据为准。

建议每个阶段完成后更新：

- 已实现功能。
- 遗留问题。
- 性能数据。
- 下一阶段任务。
